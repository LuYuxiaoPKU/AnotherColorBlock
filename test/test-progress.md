## 二、测试流程 SOP（每版本每平台同一套）

### 前置：开启测试前（每轮必做，和用户对齐）
1. **确认版本**：与用户确认本轮要测的分支 × 平台（用户拍板，不自行扩展范围）
2. **拉取产物**：从该分支最新绿 CI 下载 jar（`gh run download`，sha 与分支 HEAD 核对）
3. **准备配置**：mods 目录切换（启用目标 jar、禁用其他）、核对 jar 版本范围 vs 实例 MC 版本、
   备份被替换的旧 jar（`.old-*` 后缀）

### 测试 6 步
| 步 | 操作 | 判定 |
|---|---|---|
| ① 部署核对 | 启动前确认 mods 内 jar = 目标分支产物 | Found mod file 行 sha/文件名一致 |
| ② 启动 | 用户启动对应版本实例 | FML 加载完成，无版本范围拒绝 |
| ③ 进档 | 进入测试世界（**单存档**「op」；身份切换用 `/op self` / `/deop self`，不再双存档） | 日志 `logged in with entity id`，无 `Unrecognized argument type` |
| ④ 命令（函数批量 + 手敲抽查） | 管理员身份：`/datapack enable "file/acb-test"` → `/function acb:baseline`（12 条）→ `/function acb:deep`（4 条）；手敲 `/particleex functionlist` 看输出；玩家身份（`/deop self`）：记命令可见性/权限提示 | 无 `Failed to load function`、无 `Command exception`；functionlist 手敲有列表输出 |
| ⑤ 粒子 | 函数执行后观察客户端粒子渲染（**函数内命令输出静默，粒子目视是批量链路的主判据**） | 粒子出现（S2C payload 通路正常） |
| ⑥ 日志 | 全量扫日志 | 无 ERROR/Exception（Realms 401、UBO resize 为噪音豁免） |

### 双身份设计（2026-10-11 修订：双存档 → 单存档身份切换）
- **管理员身份**：单人世界默认 op → 测命令全量可用性
- **玩家身份**：`/deop self` 撤销 → 测无权限视角；测完 `/op self` 恢复
- 原版对照命令（每个身份都执行）：`/gamemode creative`、`/particleex`（根命令）
  - 管理员身份中原版命令若也报「未知或不完整的命令」→ 26.x 权限/剪枝全局问题（非 mod 专属）
  - 玩家身份中命令**预期不可见/无权限**（requires≥2 的正当行为），记录实际表现即可

### 命令基线（数据包函数批量 + 手敲抽查，2026-10-11 修订）
**多行命令一律走数据包函数**（聊天栏单行输入框拒收多行粘贴）。数据包已就位（`acb-test`，世界目录 datapacks/）：
- `/function acb:baseline` —— 12 条（functionlist/clearparticle/clearcache/normal×3/parameter/polarparameter/conditional/group×3/tickpolarparameter，见 test-matrix-v2.md）
- `/function acb:deep` —— 4 条深测（random()/rotateDeg 矩阵/dx-ds1-ddis/分段短路 rgbapolar）
- **手敲抽查**（函数内 sendSuccess 静默，看输出的命令必须手敲）：`/particleex functionlist`、`/particleex clearparticle`
- 单条验证（任意一条命令的参数级验证）：手敲原文（如第 1 条 normal）

## 三、判定标准

- 版本通过 = ⑥ 五步全 ✓（进档/命令/粒子/日志四项 + 部署核对）
- 记录列：**日期 / 分支 / jar sha / 平台 / 进档 / 命令 / 粒子 / 备注**
- 失败项写明现象原文 + 排查链，不猜测
- **26.x 判据补充（2026-10-11 实证）**：函数内 `sendSuccess` 全静默（vanilla 命令同证）→ 「命令」列判定 = 无 `Failed to load function`（编译）+ 无 `Command exception`（执行）+ 手敲 functionlist 有输出；粒子目视是独立主判据
